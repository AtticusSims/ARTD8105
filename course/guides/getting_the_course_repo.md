## What you are doing, and why it is not a clone

You have your own repository — the one you made in the session 1 homework, named `artd8105-<yoursurname>`. I have mine, the one you are reading now. **You need both sets of files in one folder**, so that the agent can see the course material and your work at the same time.

The obvious move is to clone my repository inside yours. **Do not do that.** A git repository inside another git repository confuses both of them: your commits stop covering the inner folder, GitHub shows an empty grey box where the files should be, and you will lose an hour to it.

What you do instead is add my repository as a **second source** for your existing one:

```
your repository  ──  origin   →  github.com/you/artd8105-yoursurname   (you push here)
                 └─  course   →  github.com/AtticusSims/ARTD8105        (you only pull)
```

One folder. One repository. Two places it talks to. My files land alongside yours, `my_work/` stays entirely yours, and when I publish something new you type one command and have it.

## Path A — you have a repository already

This is where you should be if the session 1 homework went as planned.

**Commit whatever you have first.** A pull on top of uncommitted changes is the single most common way to make a mess. Paste this:

```
Before we bring in the course files: commit everything I currently have,
with a sensible message, and push it to origin. Then confirm the working
tree is clean.
```

**Then bring in the course repository:**

```
Add the ARTD8105 course repository as a second remote called `course` and
pull it in, so that the course files sit alongside my own work in this same
repository. It is at:

    https://github.com/AtticusSims/ARTD8105.git

Our two repositories have no shared history, so the pull needs
--allow-unrelated-histories. Do not clone it into a subfolder — that would
nest one repository inside another, which I do not want.

Show me each command before you run it and tell me what it does. If
anything fails, stop and explain the error rather than trying something else.
```

**What the agent should run.** Read these, because in November you will be asked what your own repository does:

```bash
git remote add course https://github.com/AtticusSims/ARTD8105.git
git fetch course
git pull course main --allow-unrelated-histories
```

**One more command, and it matters.** Run this once:

```bash
git config merge.ours.driver true
```

This tells git that when my repository and yours have both changed something inside `my_work/`, **yours wins, silently**. Without it, that situation stops the pull and fills your file with `<<<<<<<` conflict markers — in a file you wrote. `my_work/` is yours; this is what makes git agree.

`remote add` saves the address under the nickname `course`. `fetch` downloads it without changing your files. `pull` merges it into your folder. The `--allow-unrelated-histories` flag is git refusing, sensibly, to combine two histories that never met — until you tell it that is exactly what you meant.

## From now on

Two commands, for the rest of the term:

```bash
git pull course main     # get new material from me
git push                 # send your work to your own repository
```

Or in the chat, which is what most of you will actually do:

> *"Pull the latest course material."*
> *"Commit what I did today and push it."*

**Commit at the end of every working session, not at the end of every week.** A commit is a timestamped, content-hashed record of what existed when — which is why the rubric can assess your process at all. Write the messages for the person who reads them back in session 10, because that person is you:

```
S2: parameters.md - 9 ambiguities named, 3 still undecided
S2: tool.html builds, angle spread behaves backwards from what I predicted
```

Not `update`. Not `stuff`.

## When it goes wrong

**`fatal: not a git repository`** — you are in the wrong folder. In Cursor, **File → Open Folder** and pick your project folder, not its parent and not your desktop.

**`refusing to merge unrelated histories`** — the `--allow-unrelated-histories` flag was left off. Run the pull again with it.

**`remote course already exists`** — you already did this, possibly in a previous attempt. Harmless. Ask the agent to show you where `course` points and to correct the URL if it is wrong.

**`Your local changes to the following files would be overwritten by merge`** — you edited a file outside `my_work/`. Everything in `course/`, `context/` and `.cursor/` is replaced on every pull, which is why they carry that warning at the top. Nothing is lost; ask the agent:

> *"I edited a file outside my_work/ and now the pull is blocked. Show me exactly what I changed, then help me move it into my_work/ and restore the original."*

**Authentication fails, or GitHub asks repeatedly** — use the browser sign-in Cursor offers rather than typing a password; GitHub stopped accepting account passwords over git years ago. If it loops, check two-factor authentication is actually finished on your account.

**A push is rejected as too large** — you committed a PDF, a video or a camera raw file. Do not try to rewrite history yourself:

> *"A push is failing because of a large file. Show me which file and how big, then walk me through removing it from history one command at a time, explaining each before I run it."*

**Anything else** — the agent has your terminal and can read the actual error, which is more than I can do from the front of the room. Paste the error in and ask what it means. If you are still stuck after ten minutes, ask me in class or email me. Arriving stuck costs you a session; asking costs you nothing.
