## Why you are doing this

Three reasons, in order of how much they matter to you.

**Your work cannot be lost.** Every version of everything, permanently, on someone else's servers. Design students lose work to dead laptops every year.

**Your commit history is timestamped evidence.** The log your agent keeps could in principle be edited. Git commits carry machine timestamps and content hashes. Together they are a much stronger record of when you did what — and the rubric assesses provenance.

**The messy history is the point.** Do not tidy it. Do not squash. The false starts, the reverted experiments, the commit at 2am that says "why does this not work" — that is the evidence of process that a clean repository destroys.

You do not need to learn git properly. You need about six commands, and the agent runs most of them for you.

## Part 1 — Install and identify yourself

**Install git**

- **Windows** — [git-scm.com/download/win](https://git-scm.com/download/win). Accept every default.
- **macOS** — open Terminal, type `git --version`, press enter. If it is not installed macOS offers to install it.

**Tell git who you are.** Once, ever. Open Terminal (macOS) or Git Bash (Windows):

```bash
git config --global user.name "Your Name"
git config --global user.email "your.email@um.edu.mo"
```

Use your UM email — it is what links your commits to you.

1. Sign up at [github.com](https://github.com) using your **UM email address**.
2. Apply for the **GitHub Student Developer Pack** at [education.github.com/pack](https://education.github.com/pack) — free, gives you unlimited private repositories and other tools. Approval takes a day or two, so do it in the first week.
3. Turn on two-factor authentication. GitHub requires it and you will be locked out later if you skip it now.

## Part 3 — Create your repository

**On GitHub:**

1. Click **+** → **New repository**
2. Name it `artd8105-<yoursurname>` — for example `artd8105-chan`
3. Set it to **Private**
4. Do **not** initialise with a README
5. Create

**On your machine**, in Cursor's terminal, from inside your project folder:

```bash
git init
git add -A
git commit -m "S0: workspace initialised"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/artd8105-yoursurname.git
git push -u origin main
```

GitHub will ask you to authenticate. Use the browser sign-in it offers.

**Then add the instructor as a collaborator:**

Repository → **Settings** → **Collaborators** → **Add people** → enter the instructor's GitHub username → **Read** access is enough.

That is the whole setup. Everything after this is one command.

## Part 4 — The rhythm

**At the end of every workbook step**, and at the end of every working session:

```bash
git add -A
git commit -m "S5: literature verification, three questions killed"
git push
```

The agent will run these for you if you ask. From `research_agent.md` §0 and the logging spec, it should be doing this at each step boundary — but check that it is, and run it yourself when it does not.

**Commit message format:**

```
S<step>: <what changed>
```

Examples that are useful later:

```
S3: 8 candidate questions drafted
S4: eva-london venue file, phase 5 validation FAILED, re-deriving
S8: third print failed - warping at 0.2 layer height
S9: intro rewritten after claim v4
```

Examples that are not:

```
update
stuff
asdf
```

You will read these back in session 10 when you analyse your own process. Write them for that reader.

## Part 5 — What goes in, what stays out

**Commit:** everything textual and small. Code, markdown, reading notes, the venue files, the process journal, the research log, drafts, small images, `.csv` data.

**Do not commit:** large binaries. Video files, `.blend` files over ~50 MB, raw photogrammetry captures, STL files over ~50 MB. GitHub rejects anything over 100 MB and slows badly well before that.

Create a `.gitignore` file in your project root:

```
# Large media — keep locally and in your own backup
*.mov
*.mp4
*.blend1
*.zip

# OS clutter
.DS_Store
Thumbs.db

# Cursor local state
.cursor/
```

For large artifacts, commit a small **placeholder note** instead — filename, size, where the real file lives, and a low-resolution still. That keeps the record complete without breaking the repository.

**Nothing containing other people's personal data goes in the repository.** If your project involves participants, that material lives wherever your ethics approval says it lives, not here.

## Part 6 — When it goes wrong

**"fatal: not a git repository"** — you are in the wrong folder. `cd` into your project folder.

**Push rejected, "updates were rejected"** — someone or something changed the remote. Run `git pull --rebase` then `git push`.

**Committed something huge by accident and now push fails** — do not try to fix history yourself. Ask the agent:

```
I accidentally committed a large file and the push is failing.
Walk me through removing it from history, one command at a time,
and explain what each does before I run it.
```

**Merge conflict** — you will probably never see one, since you are working alone. If you do, ask the agent and read what it tells you before accepting anything.

**Lost work** — you almost certainly have not. Ask the agent to help you look through `git reflog`. Git keeps far more than people expect.

## Part 7 — For the instructor

**Access.** Students add the instructor as a read-only collaborator in the session 1 homework. Verify in session 2 that this actually happened — it is the single most commonly skipped step and it is invisible until you need it.

**Programmatic collection.** With read access to each repository, cloning the whole cohort is one script. Create a text file of repository URLs, then:

```bash
# clone or update every student repo
while read url; do
  name=$(basename "$url" .git)
  if [ -d "$name" ]; then (cd "$name" && git pull --quiet); else git clone --quiet "$url"; fi
done < repos.txt
```

Run it weekly. It gives you an independent, timestamped snapshot of the cohort's work that does not depend on students submitting anything.

**Useful queries once you have the clones:**

```bash
# commit timeline per student — activity distribution across the term
git log --pretty=format:"%ad %s" --date=short

# how many decision records exist
ls _research_log/decisions/ | wc -l

# lines of research log per week
wc -l _research_log/sessions/*.jsonl
```

**A GitHub Classroom alternative.** [classroom.github.com](https://classroom.github.com) automates repository creation and instructor access from a roster. Worth setting up if the manual collaborator step proves unreliable, though it is more configuration up front.

**End of term.** Repositories are exported and archived to UM OneDrive as part of the research record — see the ethics brief. GitHub is a teaching tool during the semester; it is not the approved research storage location.
